Scenario A · Greenfield

New product

Nothing designed yet.

  1. Start from scratch, your AI-ready DS, or a reference template
  2. Reads your brand and inspiration files, or asks a brand color and industry
  3. Builds the DS in build order
Scenario B · Brownfield

Screens, no DS

Screens or screenshots exist in Figma.

  1. Extracts colors, fonts, spacing from the screens
  2. Approve the merges, create the DS file
  3. Builds the DS, then rebuilds the screens on it
Scenario C · Brownfield

Imperfect DS + screens

A DS exists but screens follow it partly.

  1. Where is the DS? Own library, or inside the Design file (split or keep)
  2. Maps variables, fixes the DS, audits each screen
  3. Approve the fixes, publish, Accept updates
Scenario D · Code to Design

Coded app

A repo is the source; Figma screens are the goal.

  1. Share the repo, then pick an existing DS or a new DS from the code
  2. Reads routes, popups, states and tokens
  3. Existing DS: adds only missing parts on one page. New DS: builds it from the code
  4. Builds every screen and popup, keeps your manual edits
4FoundationCheckpoint 1
  1. Open the DS file in Figma
  2. Primitives, then Semantics (Light / Dark)
  3. Spacing, radius, size and typography variables, then text and effect styles
  4. Icons from the library you picked, the App Icon page, and linked Colors / Typography pages; fixes any gaps
  5. Checks every token name (typos, stray spaces, duplicates, raw values in Semantic colors) and fixes them in your copy New
  6. Team projects: locks the foundation while editing and pushes after the step
  7. Approve the Foundation
    Approve, go to componentsRequest changes
5ComponentsCheckpoint 2
  1. Atoms, then Molecules, Organisms, Patterns; each with its description and real icons
  2. Team projects: locks each component before editing, so two people never change the same one
  3. Every Figma change reads its token bindings back on the spot, so nothing is left hardcoded by accident New
  4. Audits every variant in Light and Dark and gives each component a readiness score out of 100 New
  5. Approve the components
    ApproveRequest changes
  6. One to-do list: rename the file if needed, publish the library, Accept updates in the Design files
    All doneSome are doneNot yet
