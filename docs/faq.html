FAQ and troubleshooting

When something breaks

The problems people hit more than once, and the fix for each. Collected from the workflow's lessons log. FigCli commands run inside your figma-cli folder.

FigCliDesktop BridgeSetupTeamStorybookWorkflow

Nothing matches. Ask Claude in the workflow folder; it reads the same lessons log.

FigCli (Yolo mode)

Commands are slow or time out after 60 seconds

The FigCli daemon lost its connection token ("token mismatch"), so every command falls back to a slow direct connection.

Fix: run node src/index.js daemon status. If it is unhealthy, restart it with the same file set: FIGMA_FILE="<file name>" node src/index.js daemon restart. A restart without FIGMA_FILE breaks the token again on the next command.

FigCli stopped working after Figma updated

A Figma update replaces the app, so the Yolo patch is gone.

Fix: open a terminal as administrator inside the figma-cli folder, run node src/index.js connect, then node src/index.js daemon restart.

The first command after connecting fails

The daemon is usually still loading the open files.

Fix: node src/index.js daemon restart, then try again.

Changes went to the wrong Figma file

With several files open, a command without FIGMA_FILE goes to the last connected file, not the one on your screen.

Fix: keep only the files you need open, and make sure the name Claude uses is unique. FIGMA_FILE matches part of a name, so with "Design System" and "Design System (Copy)" open, use "Design System -" or the full name. Claude checks the file name before every first write and writes nothing on a mismatch.

Screenshots or exports come back blank or fail

Fix: bring the file to the front tab in Figma Desktop, then ask Claude to retry.

An audit result looks cut off or is not valid JSON

FigCli cuts command output at 20,000 characters.

Fix: ask Claude to return counts only or split the audit by page. A truncated file is never used as an audit report.

Claude Code blocks a figma-cli command

Auto mode may stop FigCli commands that write to Figma.

Fix: allow the command when Claude asks, or run it yourself.

Should I use Safe mode or Browser mode?

No. Safe mode was not stable in testing, and Browser mode runs outside Figma Desktop. Use Yolo, or the Desktop Bridge where patching is not allowed.

Is the Yolo patch safe? How do I undo it?

It modifies the Figma app and opens local port 9222 without a password, so any program on your computer can reach your open files while Figma runs. It is not reachable from the network. Use it on a computer you control.

Undo: node src/index.js unpatch.

Desktop Bridge and Figma token

Claude can't see the Desktop Bridge tools

Fix: restart Claude Code after adding the MCP server, then run the Figma Desktop Bridge plugin in your file (Plugins > Development) and say "Check Figma status".

The Desktop Bridge disconnected after the Yolo patch

Fix: Figma restarted, so run the Desktop Bridge plugin again in your file.

Reading Figma comments fails with "401 Invalid token"

Comments come only from the Figma REST API, and the token is read only when Claude Code starts.

Fix: make sure the token has the Comments (Read) scope, then quit Claude Code fully and start a new session. You edit the token; Claude never reads or writes it.

Claude never notices my manual edits in Figma

The edit check needs a Figma token with the File versions (Read) scope. Without one it is skipped silently.

Fix: set up the token when Claude offers it (once per computer). If the token is refused or the file is not found, Claude says so once: replace the token, or fix the DS file key in the project's status.json.

Which tool creates slots?

Only the Desktop Bridge. With both tools installed, Claude uses FigCli for everything else and asks you to open the Desktop Bridge plugin only for slots.

Setup and computer

"Python was not found" or a Stop hook error

Old versions of the workflow ran hooks with Python. Hooks now run on Node.js and skip anything optional that is missing.

Fix: update your copy of the workflow (git pull). If python opens the Microsoft Store, turn off python.exe and python3.exe in Settings > Apps > Advanced app settings > App execution aliases.

Node.js is missing and nothing offers to install it

Fix: double-click Setup-Windows.cmd or Setup-Mac.command in the workflow folder. If you start Claude anyway, it notices the hooks did not run and offers to install Node.js.

I installed something and want the computer checked again

Fix: node .claude/hooks/run.cjs setup_check --force.

A PowerShell installer rejects its arguments

With powershell -File, a comma list reaches the script as one string.

Fix: in an open PowerShell window, run Set-ExecutionPolicy -Scope Process Bypass -Force; and then the script with its arguments, in the same window.

Where do the Figma tools go?

Outside the workflow folder, in a Tools folder at a drive root (for example <drive>:\Tools). Never copy them into the repo. Check what is installed with python tools/figma_tools_check.py.

Team projects

"Join a team project" can't clone the repo

The repo is private, so you need access.

Fix: ask the project owner to add you as a collaborator on GitHub, check the link, then pick Try again.

A folder with that project name already exists

Claude never overwrites it. Pick "Use the existing folder", or rename the old folder first if it is not the team copy.

Teammates' work was not pulled at session start

Your copy and GitHub have both changed, or the pull failed.

Fix: pick "Show me the differences" and resolve it with Claude. It never force-pushes, resets or discards work.

A component is locked by a teammate

Claude says who holds it and since when. Work on something else, wait, or take over only when the teammate agreed or the lock is older than two days.

See locks: node tools/team_sync.cjs "My Projects/<Project>" --status.

Can we go back to Solo?

Yes, tell Claude. The project stops pushing; the repo stays as it is, and deleting it is up to you.

Storybook

Storybook doesn't match Figma anymore

Fix: at the start of a session, pick the project and choose "Resync now". Claude updates it from the DS file and reruns the name and style checks; it is called synced only at 100% fidelity.

The Storybook MCP doesn't show in my AI tool

The MCP server runs only while Storybook runs, and it is registered per computer, never committed.

Fix: start Storybook, then register http://localhost:6006/mcp once with claude mcp add --transport http <name> http://localhost:6006/mcp --scope local. Steps: README.

The GitHub check on a team project is red

It reruns the Figma name check, the build and the style check on every push.

Fix: ask Claude to read the failing check and fix it before more Storybook work.

Using the workflow

I picked the wrong answer

Pick Back on the next menu, or type "back to 0.4" in Other. If Figma was already changed, Claude asks whether to keep that work or undo it first.

I only want one component or one audit

Pick "Quick task" at the start, or run /ds-quick <task>. It skips the project setup but still audits the result.

Another AI tool worked in the folder

Codex, Cursor and others log their changes in the project's CHANGELOG.md. At the next session Claude tells you what they did and audits it before building on it.

Why did Claude stop and ask me to approve?

The Foundation, Components and Screens checkpoints always wait for you. Claude never approves its own work. A flow of screens also starts with a flow map (every screen, its loading, error and empty states, and where each choice leads) that you approve before any screen spec.

What does the readiness score in an audit mean?

Each component gets a score out of 100 from the audit counts: missing states weigh most, then hardcoded values, then accessibility, then naming. 90 and up is Production ready, 75 to 89 Nearly ready, 50 to 74 Needs work. It tells you which component to fix first; a checkpoint still needs every count at 0.

The token name check reports errors on a reference template

The original templates are never changed, so their typos and stray spaces stay there. When a project starts from one, Claude fixes the same names in your copy during Fix on create and lists anything it could not rename safely in gaps.md.

How do developers' AI tools use the design system?

At the end of a build Claude writes DESIGN.md and an AGENTS.md block in the project folder: tokens per mode, type, spacing, radius, components and the do's and don'ts. Cursor, Codex, Claude Code and similar tools read them, so generated UI uses your components and tokens. Rerun python tools/design_md.py "My Projects/<Project>" after a resync; your own Overview and rules between the manual markers are kept.

Claude says a Figma script "did not read its result back"

Figma sometimes accepts a token binding silently without applying it. Every script that changes Figma now ends by reading its bindings back, and the reminder appears when one did not.

Fix: nothing for you to do; Claude runs DS.readBack on the changed layers and fixes anything left hardcoded.

We want to retire a component

Ask Claude to deprecate it. It counts where the component is used, marks it [Deprecated] with its replacement, swaps the instances in your Design files one file at a time, and removes it only when nothing uses it anymore. The reason goes into the project's docs/decisions.md.

Found a new problem? Tell Claude in the workflow folder. Every fix is logged in memory/lessons.md; recurring ones are added here.
