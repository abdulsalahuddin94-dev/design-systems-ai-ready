Getting started

From zero to "Start"

Everything a new person does once on their computer, then how to work alone or with a team. Exact commands and versions live in the README Setup; this page is the short path through it.

What you need

Account

Claude Code

In the desktop app or the terminal. Other agents (Codex, Cursor, Gemini) also work through AGENTS.md.

App

Figma Desktop

The web app is not enough: both Figma tools talk to the desktop app.

Installed for you

Node.js, Python, Git

The setup file in step 2 installs whatever is missing.

Setup, once per computer

  1. Get the workflow

    Easiest: open Claude Code and paste the repo link github.com/abdulsalahuddin94-dev/design-systems-ai-ready, and ask it to clone it. You can also git clone it or download the ZIP. Any folder works, because every path inside is relative.

  2. Double-click the setup file

    Setup-Windows.cmd on Windows (click Yes when Windows asks) or Setup-Mac.command on a Mac (type your password). It installs what is missing: Node.js 18+, Python 3, Git and Figma Desktop.

    Skipped it? The first time you open the folder in Claude, it checks the same list and offers to install. Once everything is found, this computer is never checked again.

  3. Connect Figma

    You need at least one Figma tool. Paste its GitHub link to Claude and it walks you through the install.

    ToolPick it when
    FigCli, Yolo mode RecommendedYou control the computer. Fast, no plugin to keep open, Figma can stay minimized, far fewer tokens. You run one patch command as administrator.
    Desktop BridgePatching Figma is not allowed on your computer, or you need slots (FigCli cannot create them). It does all the work on its own if it is your only tool.

    Risks of the Yolo patch and every install step: Figma_Tools/README.md.

  4. Optional: a Figma token

    A Figma personal access token lets Claude notice edits made directly in Figma (so the Storybook can be resynced) and read file comments. You create it in Figma > Settings > Security and add it to the tool's config yourself; never paste it into the chat. Claude offers this once per computer.

  5. Say "Start"

    Open Claude Code in the workflow folder and say Start (or run /design-system-intake). Claude checks your Figma tools, then asks one question at a time with arrow-key menus. The recommended answer is always first, and every menu after the first has Back.

Your first session

  1. Quick task or full project? A quick task (one component, one audit, one fix) skips the project setup. A full project builds a whole design system with three approval checkpoints.
  2. Which project? Start a new one, continue an existing one, or join a team project.
  3. Creates My Projects/<Project>/ from the template, with an Inputs folder for your brand files, inspiration, screens and research.
  4. Answer the intake, then approve the Intake Summary. Nothing in Figma changes before that "yes".

Every question and stage is on the Workflow map. When the build is done, the project folder also gets DESIGN.md and AGENTS.md, so developers' AI coding tools build with your components and tokens.

Prefer buttons to a terminal?

Double-click Start-Dashboard.cmd (Windows) or Start-Dashboard.command (Mac) in the workflow folder. Your browser opens the dashboard: start or open a project, answer every question with buttons, approve screenshots in cards and update the workflow with one click. It is the same Claude Code underneath, with the same skills and rules, so you can switch to the terminal at any time with Open in Claude Code. The Style library page lists 138 looks (colors, type, radius, mood) to start a new project from. Add to the workflow adds a reference design system, an icon library, a skill from GitHub or a style and tells you what you need first. The Permissions pill sets Auto (Claude asks only before risky steps) or Ask every time. Settings shows your AI tools, sign-ins and usage.

Working as a team

Solo or Team

Right after the project folder is created, Claude asks once: "Will anyone else work on this design system with this workflow?"

Solo · Recommended

Just you

Nothing extra: no repo, nothing pushed. You can switch to Team later.

Team

One shared project

The project folder becomes one private GitHub repo that also holds its Storybook. Everyone shares one changelog, one status and one Storybook.

Start a team project (owner)

  1. Pick Team

    Claude asks before creating anything, then makes a private repo named <project>-design-system (or uses a repo link you give it) and pushes the project folder.

  2. Add your teammate

    On GitHub: the repo's Settings > Collaborators. In Figma: share the DS file and the Design files with them. Claude never invites anyone for you.

  3. Send them the repo link

    That link is all they need to join.

Join a team project (teammate)

  1. Do the setup above

    Get the workflow, run the setup file, connect a Figma tool.

  2. Say "Start" and pick "Join a team project"

    Paste the repo link. Claude clones it into My Projects/ under the same name your teammates use, so you never place folders by hand. If cloning fails, ask the owner to add you as a collaborator.

  3. Continue like any project

    You get the resume line ("Last time … Next step …") and pick your Figma tool for this computer.

What happens every session

  1. Start: pulls teammates' work and tells you who changed what.
  2. Before editing a component: locks it, so two people never change the same component. The foundation locks as one item.
  3. A teammate holds the lock? Claude says who and since when.
    Work on something elseWaitTake over
  4. After each step: pushes the change and releases the lock.
  5. Pull or push blocked: stops and shows you the differences. It never force-pushes or throws work away.

Full rules for Claude: steps/team.md. Stuck? See the Team FAQ.
