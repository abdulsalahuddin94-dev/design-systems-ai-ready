#01 What's a design system
01 · What's a design system?
not a Figma filenot a component librarynot a style guide

It's the single source of truth that connects design decisions to product code.

What's inside
tokens
colors, spacing, type scales
components
buttons, inputs, cards
patterns
how and when to use them
guidelines
voice, accessibility, layout
documentation
the why behind every decision
Designersuse it to stay consistent
Developersuse it to stop rebuilding
Productsuse it to ship faster

#01 The problem
The problem

Design systems are slow to build, slow to maintain, and always behind.

Designersdesign in Figma, nobody reads it
Developersrebuild everything from scratch
Docsget stale the day they're written
Tokensdrift from the source
Handoffa screenshot and a prayer

The system exists to create consistency, but the process of maintaining it is anything but. And an AI agent reading a raw file guesses:

#04 Figma
04 · Figma

The bridge between
design and agents.

FigCli · Yolo mode

Recommended

Talks to the Figma app directly. Reads, bulk writes, builds, screenshots and audit scripts. A full file check runs in about 15 seconds.

Desktop Bridge · MCP

When needed

The Figma plugin route. Used for slots and Figma comments, and for teams that can't patch the app.

build components with properties

read and fix comments ✅

#05 The process
05 · The process

Five verbs turn a model into a design-system team.

01

context

Give the agent the whole picture before it touches Figma.

  • intake, one question at a time
  • Inputs/: brand, screens, research
  • reference library: 4 studied DSs
  • knowledge base JSON per DS
02

persist

Nothing is re-asked, nothing is forgotten.

  • Project_Brief.md
  • CHANGELOG.md + status.json
  • memory/decisions.md
  • lessons.md: every fix
03

specialize

The right expert for each platform and job.

  • Web · Tailwind
  • iOS · Apple HIG
  • Android · Material 3
  • auditor, extractor, docs writer
04

automate

Repeatable work runs as code, not memory.

  • 22 tools: tokens, recolor, contrast
  • icons fetched from 7 libraries
  • docs + Storybook generated
  • hooks on every session
05

govern

People approve. Audits prove it.

  • 3 checkpoints, no self-approval
  • audit after every build step
  • rules.json off-limits
  • guard: never detach

#06 Cases
06 · Cases we handle

One intake, every starting point.

A

New from scratch

Brand color and font in, a complete system out: tokens, components, docs, Storybook.

B

Extract from screens

Reads unstructured UI, pulls colors, type and spacing, maps them to variables.

C

Refactor an existing DS

Variable map with confidence, fixes unlinked screens, flattens alpha colors by OKLCH match.

D

Code to Design

Reads a codebase's tokens, routes and states, and builds its screens in Figma.

Mobile, three ways

Native (separate iOS and Android), Cross-platform (one DS), or Mobile Adaptive: both platforms and EN/AR in one file through modes.

Quick mode

One task on a live file, like one component or one audit, without the full intake. Same rules and audit.

Extras

A DS hidden inside a Design file gets split into a library. Figma comments are read, fixed and marked ✅.

Atomic design: never build a tier before the one below it

built from tokens
