components

patterns

#04 Storybookmobile
04 · Storybook · mobile

Storybook is web. Our mobile isn't.

  1. Native look, web engine. Components are React + CSS replicas styled to Apple HIG or Material 3, inside a device frame (iOS 393×852, Android 412×915).
  2. Developers never see CSS names. Every token, text style and property shows the SwiftUI or Jetpack Compose name they type, with the Figma name next to it.
  3. Tokens as code. DesignTokens.swift and DesignTokens.kt download from Foundations › Code.
  4. One file, one Storybook. Mobile Adaptive projects get a Platform switch that mirrors the Figma OS mode, plus Color and Language. One platform at a time.
  5. Arabic for real. AR flips to RTL and translates the docs; code names stay exact.

#04 Agents vs skills
04 · Agents vs skills

Who does the work, and how it gets done.

Agenta persona
  • has a role and its own tools
  • owns a domain: audit, tokens, docs
  • decides what to do next
  • works in its own context window, then reports back
Skilla recipe
  • a SKILL.md with steps and rules
  • solves one kind of task
  • knows how to do it, the same way every time
  • reusable by any agent, even Codex or Cursor
In this repo
main agentuses intake + Web / iOS / Android skills, figma-use, figma-generate-library
ds-auditoruses audit-design-system · read-only, never edits Figma
token-extractorruns build_tokens.py · writes data/tokens.json
docs-writerwrites the project's own skills from what is in Figma

The main agent runs a skill; the skill says when to hand work to a specialist. One agent, many skills. One skill, many agents.

#05 The process
05 · The process

Five verbs turn a model into a design-system team.

01

context

Give the agent the whole picture before it touches Figma.

  • intake, one question at a time
  • Inputs/: brand, screens, research
  • reference library: 4 studied DSs
  • knowledge base JSON per DS
02

persist

Nothing is re-asked, nothing is forgotten.

  • Project_Brief.md
  • CHANGELOG.md + status.json
  • memory/decisions.md
  • lessons.md: every fix
03

specialize

The right expert for each platform and job.

  • Web · Tailwind
  • iOS · Apple HIG
  • Android · Material 3
  • auditor, extractor, docs writer
04

automate

Repeatable work runs as code, not memory.

  • 30 tools: tokens, recolor, style check, token names
  • icons fetched from 7 libraries
  • docs + Storybook generated
  • hooks on every session
05

govern

People approve. Audits prove it.

  • 3 checkpoints, no self-approval
  • audit after every build step
  • rules.json off-limits
  • guard: never detach
05 governfeeds back into 01 context: every fixed mistake becomes a rule in lessons.md, and the next run reads it first.

#06 Cases
06 · Cases we handle

One intake, every starting point.

A

New from scratch

Brand color and font in, a complete system out: tokens, components, docs, Storybook.

B

Extract from screens

Reads unstructured UI, pulls colors, type and spacing, maps them to variables.

C

Refactor an existing DS

Variable map with confidence, fixes unlinked screens, flattens alpha colors by OKLCH match.

D

Code to Design

Reads a codebase's tokens, routes and states, and builds its screens in Figma.

Mobile, three ways

Native (separate iOS and Android), Cross-platform (one DS), or Mobile Adaptive: both platforms and EN/AR in one file through modes.

Quick mode

One task on a live file, like one component or one audit, without the full intake. Same rules and audit.

Extras

A DS hidden inside a Design file gets split into a library. Figma comments are read, fixed and marked ✅.
