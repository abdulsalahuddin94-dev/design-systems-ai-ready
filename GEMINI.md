# Gemini instructions

Read `AGENTS.md` first. Ask every question with options (everything written `Ask (choice)` / `Ask (multi)` in the skills, approvals included) as a numbered list, recommended option first; the user may reply with one or several numbers or free text (Intake section 0). Figma tools: run `python tools/figma_tools_check.py`; with both installed, use the tool saved per file in `status.json > figma` (or ask); the user may switch any time (Desktop Bridge, or FigCli in Safe mode; guide `Figma_Tools/README.md`, rules in `Design_System_Intake_Skill/SKILL.md` section 0b). This repo has a live Storybook of the default Web reference design system (folder in `references.json`, today `Trianglz/storybook/`): at the start of a session, mention it in one line (information only); ask about the project first and about Storybook only at intake 0.7, for a project with pending Storybook work, or when the user asks Run it with `npm install` then `npm run storybook` in that folder (Node.js 18+, ask before installing); it serves http://localhost:6006 and a Storybook MCP at http://localhost:6006/mcp.

Building screens (Antigravity and Gemini): follow `AGENTS.md` handoff item 7 (screen fidelity) and item 8 (never approve a checkpoint yourself). Open every source screenshot before building, write the screen spec, fill every instance with the real content, build one section per script, and compare each screen side by side with its source before reporting.
