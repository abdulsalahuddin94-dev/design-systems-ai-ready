# Style library

138 visual styles (looks) a new project can start from: one folder per style, each with one `DESIGN.md` that describes its colors (hex), typography, component styling in words, spacing, radius and elevation, do's and don'ts, responsive rules and an agent prompt guide. `styles.json` is the index (slug, title, category, one-line description, `inspired_by_brand`), generated by `python tools/build_style_index.py`; never edit it by hand.

Source: [plugin87/ux-ui-agent-skills](https://github.com/plugin87/ux-ui-agent-skills), folder `design-systems/library/`, MIT, Copyright (c) 2026 Thientan Soparat. The files are copied unchanged (license in `Workflow_References/licenses/plugin87_ux-ui-agent-skills.txt`).

## Style library vs reference library

| | `Reference_Library/` (`references.json`) | `Style_Library/` (`styles.json`) |
|---|---|---|
| What it is | Studied Figma design systems | Text descriptions of a look |
| Gives | **Structure**: how we build. Figma pages, components, variants, properties, docs, file layout | **Look** only: colors, type, radius, density, elevation, mood |
| Has a Figma file | Yes (duplicated, never edited) | No |
| Used at | Every build: the platform's default entry is the structure | Greenfield intake 0.3e "Visual direction", optional |

A project picks at most one style. Its components are still built on the platform's default reference design system (`references.json`), with the same atomic tiers, names, properties and docs; the style only changes how they look.

## How the intake uses a style

Greenfield only (`Design_System_Intake_Skill/steps/style-library.md`, intake 0.3e). Brownfield, Scenario C and Code to Design never ask: their look comes from the source.
1. "Visual direction?" -> "My brand files" / "Pick a style from the library" / "No style, use defaults".
2. Pick -> a category, then a style in it. The dashboard's **Style library** page can preselect one ("Use for a new project").
3. The style's values are mapped into our layers: its hex colors -> Primitives (ramps from `tools/new_foundation.py`) -> our Semantic layer, contrast checked; its font prefills 0.6 (a proprietary font is replaced by the free substitute the file names); radius, spacing and elevation are snapped to our scales.
4. All prefilled values are shown once with "Use these (Recommended)" / "Change something", and the choice is recorded in `Project_Brief.md` and `status.json > style`.

## Brand-inspired styles

82 styles are named after a company or product (`inspired_by_brand: true`, e.g. "Design System Inspired by Stripe"). They are a mood to start from, never the company's identity:
- Say "inspired by <name>", never "the <name> design system".
- Never copy logos, wordmarks, product names, illustrations, proprietary fonts or the company's signature brand color as the client's brand.
- The client's own brand color and fonts always win (trademark); the style then gives only the neutrals, radius, density, elevation and type personality.

## Adding or updating styles

Through `/contribute` ("Add a style" in the dashboard): add `Style_Library/<slug>/DESIGN.md` with a `# <title>` line, a `> Category: <name>` line and a one-line `> ` description, check the license of its source, then run `python tools/build_style_index.py` (`--check` must pass). To refresh from upstream: `python tools/build_style_index.py --source <clone>/design-systems/library`.
